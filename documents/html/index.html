How it works

From hardware facts to sealed evidence

Five small commands, each honest about what it measured and what it only estimated.

1. Look

Read CPU, RAM, disk and NVIDIA GPU facts.

localsutra doctor
localsutra doctor --out my-pc

2. Estimate

Check which models plausibly fit.

localsutra fit \
  --catalog catalog.json

3. Prove

Run the audit and open the HTML report.

localsutra audit --out my-audit
localsutra verify \
  --report my-audit/audit-report.json

Why it is different

Estimates look like estimates

Every value in every report carries one of these labels. Nothing unknown is dressed up as a result.

measuredRead or timed on this host now. Example: RAM, disk, CPU loop timing.
heuristicCalculated from stated assumptions. Example: model-fit estimate.
runtime_reportedA local runtime told us. Example: Ollama token counters.
not_runThe test did not happen. Never counted as a pass.
unknownCannot be determined here. Not the same as absent.

Proof

Evidence you can reproduce

Run npm run proof to regenerate everything below. The latest audit verdict on the recording host is APPROVED_WITH_EVIDENCE.

What it does not do

  • It estimates memory. It does not promise a model will load or how fast it will run.
  • GPU facts come from NVIDIA nvidia-smi only. Other GPUs and NPUs are reported unknown.
  • Live inference on a real model is not run by the audit; infer is opt-in.
  • Skills are instructions for your coding agent. Native IDE activation is not verified.
  • The audit is a reproducible self-assessment, not a certification.
